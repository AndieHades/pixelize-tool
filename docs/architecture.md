# Архитектура

## Целевая платформа

Pixel Heart сейчас живёт как web/PWA-сборка, но стратегическая цель проекта —
полноценное приложение для Windows (`.exe`). Поэтому браузерные ограничения не
считаются окончательной рамкой продукта. Если поведение естественно для desktop
приложения (отдельные окна, нахождение поверх основного окна, другой монитор,
нативная работа с файлами, системная пипетка), проектируем UX и модель данных под
desktop-сценарий, а web-версия получает временный fallback.

Практическое правило: platform-specific вещи держим на краю системы. `logic/`
остаётся чистым, `core/` хранит контракты/данные, а браузерные реализации
(`window.open`, File API, DOM drag/drop и т.п.) должны быть заменяемыми адаптерами,
чтобы в Windows-сборке их можно было подменить native-window / filesystem /
OS-level API без переписывания пользовательского сценария.

## Три слоя

```
┌─────────────────────────────────────────────────────────┐
│ systems/   оркестрация: state⇄DOM⇄canvas, обработчики,   │
│            подписки на bus. Одна система = один процесс.  │
│            Системы НЕ знают друг о друге.                 │
├─────────────────────────────────────────────────────────┤
│ core/      слои-посредники + сервисы фундамента:         │
│            state (данные) · bus (события) · dom · кеш    │
│            слоёв · history. Импортируется кем угодно.    │
├─────────────────────────────────────────────────────────┤
│ logic/     чистые вычисления. Без DOM, без state.        │
│            Тестируется в изоляции.                       │
└─────────────────────────────────────────────────────────┘
```

Зависимости строго вниз: `systems → core → logic`. `logic` не зависит ни от
чего. Горизонтальных связей (`systems → systems`) нет.

## Слои-посредники

Две точки, через которые системы взаимодействуют, не зная друг о друге:

### `core/state.js` — слой данных

Единственный изменяемый объект `S`: размеры (`W`,`H`), `layers`, `cur`,
`folders`, `palette`, `active`, `tool`, выделение (`sel`/`selMask`/`selFloat`),
`view`, история (`undoStack`/`redoStack`). Плюс константы (`MAX_LAYERS`,
`MAX_SIZE`, `BP_SMAX`) и фабрики (`blank`, `newLayer`, `G`).

Поля **мутируют**: `S.cur = 2`, `S.layers.push(...)`. Биндинги не
реэкспортируются (в ESM импорт неизменяем), поэтому общее состояние живёт в
полях одного объекта.

### `core/bus.js` — слой событий

Синхронная шина `on(event, fn)` / `emit(event, payload)`. Система-источник
шлёт сигнал, не вызывая соседа; заинтересованные системы подписаны.
Синхронность сохраняет прежнее поведение прямых вызовов.

Базовые события (канон — в коде, тут ориентир):

| Событие | Когда шлётся | Кто слушает |
|---------|--------------|-------------|
| `render` | состояние изменилось, нужна перерисовка холста | system render |
| `layers` | изменился состав/порядок/имена слоёв | system layers-ui, render |
| `palette` | изменилась палитра или активный цвет | system palette |
| `selection` | изменилось выделение | system selection-ui |
| `snapshot` | зафиксировать состояние в истории | core history |

## Модель документа

- **Слой** `{ name, grid, opacity, visible, fid, clip, lock, alphaLock, symLock, ext, effects }`.
  - `grid` — `H×W` массив; клетка = `[r,g,b,a]` или `null` (пусто).
  - `ext` — `Map "x,y"→[r,g,b,a]` пикселей, ушедших за край (не теряются при
    сдвиге/кропе/повороте; ключи разбираются `parseKey`).
  - `fid` — id ближайшей папки (`folders`) или `null`. `clip` — обтравочная маска.
  - `lock` — слой нельзя править; `alphaLock` — рисование только по существующим
    пикселям (проверяются в `draw/cells.js`, `draw/adjust.js`, `move-tool`).
  - `effects` — массив неразрушающих Layer Effects `{ id, type, visible, params }`
    (`stroke`/`glow`/`dropShadow`/`innerShadow`). Пересчитываются из силуэта слоя при
    каждом изменении (`core/effects-render.js`); порядок = порядок в списке.
- **Папка** `{ id, name, open, visible, symLock, parent, effects }` — **вложенные группы**:
  `parent` — id родительской папки или `null`. Видимость/симметрия каскадом по
  цепочке предков (`folderChain`, `effVis`, `layerSymLocked`). Инвариант: все слои
  поддерева папки идут подряд в `S.layers`; список рисуется рекурсивно с отступом.
- **Документ** — снимок всего этого; несколько документов держатся в памяти,
  переключение сохраняет/восстанавливает состояние.

## Поток одного штриха (пример)

```
pointerdown ─▶ systems/input ─▶ beginStroke (core/history: emit 'snapshot')
pointermove ─▶ systems/input ─▶ systems/draw.stamp ─▶ logic/raster.blendOver
                                        │
                                        └─▶ state: мутирует G(), markDirty
pointerup   ─▶ systems/input ─▶ emit 'render' ─▶ systems/render перерисовывает
```

Никто никого не импортирует поперёк: input знает про draw как про свою же
часть пайплайна ввода (один процесс — «обработать ввод»), а сигнал на
перерисовку идёт через `bus`.

## Рендер и кеш

`core` кеширует каждый слой в отдельный `canvas W×H` (грязь помечается
`markDirty`, см. utilities.md). `render` (видимый холст), экспорт PNG/PSD и
окно-превью собирают композит из этих кешей одной функцией — `compositeLayers`.
Дублировать цикл композита нельзя.

## Точки расширения

Спроектированы заранее, чтобы добавление крупной фичи было «вставил модуль»,
а не «переписал всё». Подробности и статус — [roadmap.md](roadmap.md).

### Анимация (кадры)

Документ мыслится как **набор кадров**. Сейчас кадр один, поэтому модель
плоская (`S.layers`/`S.folders` = текущий кадр). Animator вводит контейнер
`S.animator`: кадры хранят собственные `layers`/`folders`/`bg`, таймлайны
хранят порядок кадров, fps и режим (`once`/`loop`/`pingpong`). Функции,
работающие «с документом», работают с активным кадром: при выборе кадра
Animator сохраняет текущие `S.layers`/`S.folders`/`S.bg`, затем загружает
выбранный кадр в те же поля.

`systems/animation/*` — отдельная нижняя панель и не часть панели слоёв.
Панель слоёв остаётся обычной: если на кадре выключить глаз слоя, это меняет
видимость именно выбранного кадра. Drag/drop GIF открывает Animator и
раскладывает GIF по кадрам.

Ключевые ограничения: операции со слоями относятся к активному кадру, операции
размера холста применяются ко всем кадрам, autosave перед записью сбрасывает
активный кадр в `S.animator.frames`, а history не должен копировать весь
Animator на каждый мазок. Подробный план: [animation.md](animation.md).
**Менять модель под кадры — только расширением, без слома плоского случая.**

### Персистентность и галерея

`core/storage.js` хранит документы в IndexedDB (слои, палитра, превью, время).
`systems/gallery.js` — экран выбора работ (Procreate-стиль). `core/documents`
(менеджер документов в памяти) уже есть; персистентность подключается к нему,
не меняя системы редактирования.

### Локализация и темы

Кросс-срезы, а не системы: `src/i18n/*` и `src/styles/tokens.css` — общие
ресурсы. Системы визуала берут строки из `t(...)` и цвета из токенов и
реагируют на события `bus`: `locale`, `theme`. См. [i18n.md](i18n.md),
[theming.md](theming.md).

## Сборка и деплой

ES-модули → **Vite** собирает в статический `dist/` (бандл, минификация,
хеши, code-splitting). `index.html` указывает на одну точку входа
`src/app.js`. Деплой — GitHub Actions на Pages (`.github/workflows/deploy.yml`).
Сборка идёт на CI/деве; iPad и браузеры получают готовые файлы. Vite не бандлит
классические скрипты — поэтому сборка включается по завершении миграции §1.

## Тестовый гейт

- `test/unit.mjs` — чистая логика (`logic/*`, `core/state`, `core/bus`) в node.
- `test/harness.mjs` + `test/smoke.mjs` + `test/probe.js` — приложение целиком
  в jsdom с фейковым 2D-контекстом; прогоняет сценарии по системам.
- `npm test` гоняет оба. Подробности в [systems.md](systems.md) → «Тесты».
