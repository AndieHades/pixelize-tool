# Архитектура

## Три слоя

```
┌─────────────────────────────────────────────────────────┐
│ systems/   оркестрация: state⇄DOM⇄canvas, обработчики,   │
│            подписки на bus. Одна система = один процесс.  │
│            Системы НЕ знают друг о друге.                 │
├─────────────────────────────────────────────────────────┤
│ core/      слои-посредники + сервисы фундамента:         │
│            state (данные) · bus (события) · dom · кеш    │
│            слоёв · history. Импортируется кем угодно.    │
├─────────────────────────────────────────────────────────┤
│ logic/     чистые вычисления. Без DOM, без state.        │
│            Тестируется в изоляции.                       │
└─────────────────────────────────────────────────────────┘
```

Зависимости строго вниз: `systems → core → logic`. `logic` не зависит ни от
чего. Горизонтальных связей (`systems → systems`) нет.

## Слои-посредники

Две точки, через которые системы взаимодействуют, не зная друг о друге:

### `core/state.js` — слой данных

Единственный изменяемый объект `S`: размеры (`W`,`H`), `layers`, `cur`,
`folders`, `palette`, `active`, `tool`, выделение (`sel`/`selMask`/`selFloat`),
`view`, история (`undoStack`/`redoStack`). Плюс константы (`MAX_LAYERS`,
`MAX_SIZE`, `BP_SMAX`) и фабрики (`blank`, `newLayer`, `G`).

Поля **мутируют**: `S.cur = 2`, `S.layers.push(...)`. Биндинги не
реэкспортируются (в ESM импорт неизменяем), поэтому общее состояние живёт в
полях одного объекта.

### `core/bus.js` — слой событий

Синхронная шина `on(event, fn)` / `emit(event, payload)`. Система-источник
шлёт сигнал, не вызывая соседа; заинтересованные системы подписаны.
Синхронность сохраняет прежнее поведение прямых вызовов.

Базовые события (канон — в коде, тут ориентир):

| Событие | Когда шлётся | Кто слушает |
|---------|--------------|-------------|
| `render` | состояние изменилось, нужна перерисовка холста | system render |
| `layers` | изменился состав/порядок/имена слоёв | system layers-ui, render |
| `palette` | изменилась палитра или активный цвет | system palette |
| `selection` | изменилось выделение | system selection-ui |
| `snapshot` | зафиксировать состояние в истории | core history |

## Модель документа

- **Слой** `{ name, grid, opacity, visible, fid, clip, ext, symLock }`.
  - `grid` — `H×W` массив; клетка = `[r,g,b,a]` или `null` (пусто).
  - `ext` — `Map "x,y"→[r,g,b,a]` пикселей, ушедших за край (не теряются при
    сдвиге/кропе/повороте; ключи разбираются `parseKey`).
  - `fid` — id папки (`folders`) или `null`. `clip` — обтравочная маска.
- **Папка** `{ id, name, open, visible, symLock }`. Видимость/симметрия папки
  каскадом влияют на слои (`effVis`, `layerSymLocked`).
- **Документ** — снимок всего этого; несколько документов держатся в памяти,
  переключение сохраняет/восстанавливает состояние.

## Поток одного штриха (пример)

```
pointerdown ─▶ systems/input ─▶ beginStroke (core/history: emit 'snapshot')
pointermove ─▶ systems/input ─▶ systems/draw.stamp ─▶ logic/raster.blendOver
                                        │
                                        └─▶ state: мутирует G(), markDirty
pointerup   ─▶ systems/input ─▶ emit 'render' ─▶ systems/render перерисовывает
```

Никто никого не импортирует поперёк: input знает про draw как про свою же
часть пайплайна ввода (один процесс — «обработать ввод»), а сигнал на
перерисовку идёт через `bus`.

## Рендер и кеш

`core` кеширует каждый слой в отдельный `canvas W×H` (грязь помечается
`markDirty`, см. utilities.md). `render` (видимый холст), экспорт PNG/PSD и
окно-превью собирают композит из этих кешей одной функцией — `compositeLayers`.
Дублировать цикл композита нельзя.

## Тестовый гейт

- `test/unit.mjs` — чистая логика (`logic/*`, `core/state`, `core/bus`) в node.
- `test/harness.mjs` + `test/smoke.mjs` + `test/probe.js` — приложение целиком
  в jsdom с фейковым 2D-контекстом; прогоняет сценарии по системам.
- `npm test` гоняет оба. Подробности в [systems.md](systems.md) → «Тесты».
