# Темизация (дизайн-токены)

Цель: поменять цвет/отступ/радиус = править **одно** место (токен), а не
искать значение по всему `style.css`.

## Устройство

Токены — CSS-переменные в `:root` (файл `src/styles/tokens.css`). Остальные
стили ссылаются только на них:

```css
:root {
  /* цвета */
  --col-bg:        #0d0d10;
  --col-panel:     #141419;
  --col-accent:    #ff7a18;
  --col-line:      rgba(255,255,255,.05);
  /* размеры */
  --btn:           40px;        /* размер квадратной кнопки */
  /* шкала радиусов: одинаковые элементы = один токен, не «на глаз» */
  --r-xs: 4px; --r-sm: 6px; --r-md: 8px; --r-lg: 10px; --r-xl: 12px; --r-2xl: 16px; --r-3xl: 20px; --r-pill: 999px;
  --gap:           8px;
}

.tb-group button { width: var(--btn); border-radius: var(--r-lg); }
header { background: var(--col-panel); }
```

**Скругления — только из шкалы `--r-*`** (а не `border-radius: 9px`): кнопки/
карточки/попапы берут радиус из одной шкалы, поэтому однотипные элементы
скруглены одинаково. `50%` (круги) и `0` остаются литералами. Семантические
цвета-статусы тоже токены: `--ok` (подтвердить/готово), `--danger`, `--marker`
(белые ползунки/кольца выделения).

## Правила

- **Запрещены зашитые значения стиля** (hex-цвета, пиксели «магией») вне
  `tokens.css`. В правилах — только `var(--…)`.
- Имена токенов — по смыслу (`--col-accent`), а не по значению (`--orange`):
  тему меняем переопределением, не переименованием.
- Тёмная/светлая/другие темы — это другой набор значений тех же токенов
  (`:root[data-theme="light"] { --col-bg: … }`). Переключатель темы шлёт
  `bus.emit('theme')` и ставит `data-theme` на `<html>`.

Проверка «нет зашитых цветов вне токенов» (грубая):
```bash
grep -RnE "#[0-9a-fA-F]{3,8}|rgba?\(" src/styles --include='*.css' \
  | grep -v tokens.css && echo "вынеси в токен" || echo "ok"
```

## Тумблеры (switch)

Переключатели во всём приложении — один компонент `.switch`
(`<label class="switch"><input type="checkbox"><span></span></label>`), вид
iOS/Procreate. Цвета вынесены в токены — перекрасить все тумблеры разом
можно одной правкой:

```css
--toggle-on:   var(--accent);          /* включён */
--toggle-off:  rgba(120,122,134,.5);   /* выключен */
--toggle-knob: #fff;                   /* кружок */
```

Никаких самописных переключателей — переиспользуй `.switch`, иначе вид
разъедется.

## Меню-баблы

Все всплывающие меню (контекстные, настройки) рисует один помощник
`showMenuAt` (`core/dom.js`): бабл с треугольником-указателем на точку вызова.
Вид — общий: правишь `#ctx, #lctx, #cctx, #setmenu` и `.menu-arrow` в одном
месте `style.css`, меняется везде. Плавающие окна (панель слоёв, палитра,
превью) — это не меню, треугольника у них нет.

## Анимации

Движения интерфейса вынесены в **отдельный** файл `src/styles/animations.css`
(подключён в `index.html`). Это единственное место для keyframes и переходов;
правишь анимацию — правишь его, ничего больше искать не нужно.

Длительности, кривые и масштабы — это тоже токены в `tokens.css`
(`--anim-fast`, `--anim-pop`, `--ease-out`, `--ease-pop`, `--press-scale`,
`--lift-scale`). `animations.css` ссылается только на них:

```css
.gal-actions button:active { transform: scale(var(--press-scale)); }
@keyframes pop-in { from { transform: scale(0) } to { transform: scale(1) } }
```

Так «сделать отдачу резче/мягче» = поменять один токен, а не перебирать правила.

## Связь с i18n

Переключатели языка и темы живут рядом (системные настройки приложения) и оба
работают по одному паттерну: меняют состояние → шлют событие в `bus` →
визуальные системы реагируют.
