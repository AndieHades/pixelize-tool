# Правила (контракт)

Это требования, не рекомендации. PR, нарушающий их, не проходит ревью.

## 1. Размер и декомпозиция

- **Жёсткий лимит — 170 строк на файл.** Подходишь к лимиту — дроби на модули.
  Исключение: словари локализации `src/i18n/locales/*.js` — это данные, их
  можно держать длиннее ради читаемости и синхронности ключей.
- Никаких god-файлов. Каждый модуль решает ровно одну задачу.

Проверка:
```bash
awk 'END{if(NR>170)exit 1}' src/**/*.js   # или просто wc -l
find src -name '*.js' ! -path '*/i18n/locales/*' | xargs wc -l | awk '$1>170{print "СЛИШКОМ ДЛИННЫЙ:",$2}'
```

## 2. Системы

- Каждая система отвечает за **один процесс** и описывается одной фразой.
  Нужно слово «и» в описании — это две системы, раздели их.
- Системы **не импортируют друг друга напрямую. Никогда.**
- Общение между системами — **только через слои** `core/state.js` (данные) и
  `core/bus.js` (события).
- Логика и визуал разделены (см. §3).

Что **можно** импортировать всем:

- `core/*` — слои-посредники и сервисы ядра (`state`, `bus`, `dom`, кеш слоёв,
  история). Это общий фундамент, не «система».
- `logic/*` — чистые функции. Без побочных эффектов, без DOM, без `state`.

Что **нельзя**: `systems/draw.js` ⇸ `systems/selection.js` и любые другие
связи система↔система. Нужно дёрнуть соседа — пошли событие в `bus`.

Проверка «нет импортов система→система»:
```bash
grep -RnE "from '(\.\./)?systems/" src/systems && echo "НАРУШЕНИЕ" || echo "ok"
```

## 3. Логика отдельно от визуала

- `src/logic/**` — чистые вычисления над данными (сетка пикселей, цвет,
  квантование, поворот). **Запрещены** `document`, `window`, `canvas`, импорт
  `state`. Размеры берутся из аргументов (напр. из самой сетки), не из глобалей.
- `src/systems/**` — оркестрация: читают/пишут `state`, рисуют, вешают
  обработчики DOM, шлют события. Тяжёлые вычисления делегируют в `logic/`.

Грубая проверка чистоты логики:
```bash
grep -RnE "document|window|getContext|from '.*state'" src/logic && echo "НАРУШЕНИЕ" || echo "ok"
```

## 4. Никакого дублирования

- Один и тот же расчёт/паттерн встречается дважды — вынеси в `logic/` или `core/`.
- **Перед написанием помощника проверь [utilities.md](utilities.md).**
- Каталог переиспользуемого поддерживается актуальным: добавил общий помощник —
  впиши его туда же.

## 5. Ни одной зашитой UI-строки

Все подписи/тосты/меню — через `t('ключ')`; тексты живут в
`src/i18n/locales/*`. Статика в HTML — через `data-i18n`. Подробности и
проверка — [i18n.md](i18n.md). Цель: новый язык = один новый файл локали.

## 6. Ни одного зашитого значения стиля

Цвета/размеры/отступы — токены (CSS-переменные в `src/styles/tokens.css`); в
правилах только `var(--…)`. Подробности и проверка — [theming.md](theming.md).
Цель: новая тема = переопределение токенов.

## 7. Настраиваемое — данные в `config`

Любое настраиваемое значение (предел, пресет размера, дефолт инструмента/
эффекта, тайминг жеста) живёт в `src/config/*`, а не магическим числом в
системе. `state.js` берёт стартовые значения оттуда. Подробности —
[config.md](config.md).

## 8. Хоткеи — данные, не логика

Горячие клавиши задаются картой `комбо → имя действия`
(`systems/keyboard/keymap.js`), действия регистрируются по имени в
`core/actions.js`. Никаких `addEventListener('keydown')` с разбором клавиш в
системах. Переназначение — `rebind()`. Подробности — [keymap.md](keymap.md).

## 9. Режимы галерея/эдитор разделены классом, не списком

Окно/оверлей, принадлежащее одному режиму, помечается классом контекста —
`.gallery-only` (виден только в галерее) или `.editor-only` (только в эдиторе).
CSS гасит чужой режим по построению (`body.gallery-open .editor-only` /
`body:not(.gallery-open) .gallery-only`). **Новый галерейный элемент = добавь
`gallery-only`** — он физически не «упадёт» на эдитор, вписывать id в списки не
нужно. Выход из галереи (`gallery.hide`) гасит все `.gallery-only.on` сам.

## 10. Тесты — часть определения «готово»

- `npm test` зелёный.
- Новая чистая логика → тест в `test/unit.mjs`.
- Новое поведение системы → сценарий в `test/probe.js`.
- Тест не должен зависеть от порядка: изолируй сценарий через `fresh()`.

## 11. Проектируем как Windows-приложение

Web/PWA — текущий runtime, но не конечная продуктовая рамка. Все UX-решения
оцениваются через будущую Windows `.exe`-сборку: отдельные окна, работа на другом
мониторе, OS-level пипетка, файловая система, native dialogs и always-on-top
сценарии должны быть допустимыми в модели.

- Не закрепляй браузерное ограничение как продуктовый закон, если desktop-версия
  должна уметь больше. В web можно сделать fallback, но контракт должен быть
  готов к native-реализации.
- Browser-only API (`window.open`, DOM drag/drop, File API, clipboard, storage)
  держи на краю `systems/` или в небольшом `core`-адаптере. Не протаскивай их в
  `logic/` и не завязывай на них модель документа.
- Если фича явно про окна/файлы/OS-интеграцию, описывай поведение в терминах
  desktop UX, а потом выбирай web-совместимый fallback для текущей сборки.

## Чек-лист перед коммитом

- [ ] Каждый изменённый файл ≤ 170 строк (кроме `src/i18n/locales/*.js`).
- [ ] Новый код — в правильном слое (logic чистый / systems оркестрирует / core фундамент).
- [ ] Нет импортов система→система; кросс-сигналы идут через `bus`.
- [ ] Дубли вынесены; `utilities.md` обновлён, если добавлен общий помощник.
- [ ] UI-строки — через `t(...)`, не зашиты; ключ добавлен во все локали.
- [ ] Значения стиля — через токены, не зашиты.
- [ ] Desktop/Windows-сценарий продуман; web-ограничения оформлены как fallback, а не как финальная модель.
- [ ] `npm test` зелёный; добавлены тесты на новое поведение.
