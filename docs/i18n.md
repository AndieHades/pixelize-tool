# Локализация (i18n)

Цель: перевести интерфейс на новый язык = добавить **один** файл локали.
Никаких строк в коде.

## Устройство

```
src/i18n/
  index.js            t(key, vars?) · setLocale(code) · current · detect()
  locales/ru.js       { 'tool.pencil.title': 'Карандаш (B)', … }
  locales/en.js       { 'tool.pencil.title': 'Pencil (B)', … }
```

- `t('ключ', {n: 3})` → строка текущей локали; `{n}` подставляется из `vars`.
- Дефолт — `ru` (текущий язык). Старт: `detect()` берёт сохранённый выбор из
  localStorage, иначе `navigator.language`, иначе `ru`.
- `setLocale('en')` меняет язык, сохраняет выбор и шлёт `bus.emit('locale')`;
  системы визуала по событию перерисовывают подписи.

## Правила

- **Запрещены зашитые UI-строки** в `index.html` и в `src/`. Только `t(...)`.
- Статические подписи в HTML помечаются `data-i18n="ключ"` (для `title` —
  `data-i18n-title`); при старте и при смене языка их проставляет
  `i18n/index.js`, проходя по `[data-i18n]`.
- Динамические строки (тосты, пункты меню, статус) строятся через `t(...)`
  прямо в системе.
- Ключи — по неймспейсам: `tool.*`, `menu.*`, `toast.*`, `panel.*`, `dialog.*`.
- Любой новый ключ добавляется **во все** локали разом; отсутствующий ключ
  возвращает сам ключ (видно в UI — значит, забыли перевести).

Проверка «нет зашитых строк» (грубая):
```bash
grep -RnE ">[А-Яа-яA-Za-z].*<" index.html | grep -v data-i18n   # подписи без ключа
```

## Добавить язык

1. Скопировать `locales/ru.js` → `locales/xx.js`, перевести значения.
2. Зарегистрировать `xx` в списке локалей `i18n/index.js`.
3. Готово — переключатель языка подхватит автоматически.
